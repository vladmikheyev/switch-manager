ОПИСАНИЕ
----------------------------------------------------------------
Switch Manager - веб-приложение для инвентаризации, учёта и 
управления сетевым оборудованием (коммутаторы и SFP-модули).
Позволяет вести базу устройств, отслеживать историю изменений, 
гибко фильтровать данные, экспортировать отчёты и прикреплять 
технические спецификации (PDF).

ОСНОВНЫЕ ВОЗМОЖНОСТИ
----------------------------------------------------------------
[+] Учёт коммутаторов: полное CRUD, поля: название, модель, 
    S/N, порты, статус, локация, сотрудник, заявка, комментарий.
[+] Учёт SFP-модулей: отдельная вкладка с учётом вендора, модели, 
    дальности, цвета, статуса, остатков (шт.).
[] История изменений: автоматический лог для каждого устройства 
    (кто, когда, какие поля изменил, хранит до 100 записей).
[+] Умный поиск: фильтрация по всем текстовым и числовым полям 
    (включая комментарии, дальность, количество).
[+] Статусы и фильтры: быстрый отбор по статусам (ЗИП / В работе / 
    Заказано), мгновенный подсчёт физических единиц.
[+] Дублирование записей: копирование SFP с автоочисткой системных 
    полей для быстрого массового ввода.
[+] Экспорт данных: выгрузка отфильтрованного списка в .xlsx (Excel) 
    и .json (бэкап/импорт).
[+] Документы: загрузка PDF-даташитов с хранением в backend/uploads/ 
    и просмотром в новой вкладке.
[+] Безопасность: локальный режим (127.0.0.1), rate limiting, 
    валидация запросов, защита от XSS.
[+] UI/UX: компактные хедеры, адаптивные таблицы, счётчики, 
    цветовая индикация статусов и типов кабелей.

ТЕХНОЛОГИЧЕСКИЙ СТЕК
----------------------------------------------------------------
Фронтенд:    React 18, Vite, Tailwind CSS, Lucide React, xlsx
Бэкенд:      Node.js 20+, Express 4, Multer, Helmet, CORS, RateLimit
Хранение:    JSON-файлы (flat-file DB), файловая система для документов
Инфраструктура: Nginx (reverse proxy & статика), Windows Batch

УСТАНОВКА И ЗАПУСК
----------------------------------------------------------------
Требования: Node.js v18+, npm v9+, Nginx (опционально)

1. Установка зависимостей:
   cd switch-manager
   npm install
   cd backend
   npm install
   cd ..

2. Режим разработки (два терминала):
   Терминал 1: cd backend && npm run dev
   Терминал 2: npm start
   Доступ: http://localhost:3000 | API: http://localhost:5000

3. Локальный режим (через Nginx, порт 8088):
   Запустите от имени администратора:
   .\stop-start-App+nginx-LOCALHOST.bat
   Скрипт автоматически остановит старые процессы, запустит 
   бэкенд, фронтенд и Nginx, проверит доступность сервисов.

API И МАРШРУТЫ
----------------------------------------------------------------
GET  /api/health                  - Проверка статуса сервера
GET  /api/switches                - Список коммутаторов
POST /api/switches                - Создать коммутатор
PUT  /api/switches/:id            - Обновить
DELETE /api/switches/:id          - Удалить
GET  /api/switches/:id/history    - История изменений
POST /api/switches/upload/:id     - Загрузить файл

GET  /api/sfp                     - Список SFP-модулей
POST /api/sfp                     - Создать SFP
PUT  /api/sfp/:id                 - Обновить
DELETE /api/sfp/:id               - Удалить
GET  /api/sfp/:id/history         - История изменений SFP
POST /api/sfp/upload/:id          - Загрузить PDF-даташит
DELETE /api/sfp/document/:id/:file - Удалить документ

БАЗА ДАННЫХ И ФАЙЛЫ
----------------------------------------------------------------
- Данные хранятся в backend/data/switches.json и sfp_modules.json
- Формат: плоский JSON-массив. Создаётся автоматически при первом запуске.
- История хранится внутри каждого объекта в поле `history` (max 100 записей).
- Загруженные файлы сохраняются в backend/uploads/ с уникальными UUID-именами.
- Оригинальные имена, MIME-типы и размеры записываются в JSON.

УСТРАНЕНИЕ НЕПОЛАДОК
----------------------------------------------------------------
[!] Порт 5000/3000 занят
    Решение: taskkill /f /im node.exe -> перезапуск

[!] Ошибка "Module not found" или сборка падает
    Решение: удалите node_modules/.vite, выполните npm install

[!] Nginx не запускается
    Решение: nginx -t -> проверьте пути в nginx.conf, убедитесь, 
    что папка C:\nginx существует и права доступа разрешены.

[!] Файл не загружается ("Файл не выбран" или 404)
    Решение: убедитесь, что frontend отправляет FormData без 
    ручного заголовка Content-Type. Проверьте маршрут /api/sfp/upload/:id.

[!] В браузере отображается старая версия
    Решение: Ctrl + F5 (жёсткая перезагрузка) или включите 
    "Disable cache" в DevTools -> Network.

[!] Ошибка "listen EADDRINUSE"
    Решение: полностью завершите процессы node.exe через 
    taskkill /f /im node.exe перед повторным запуском.

РЕЗЕРВНОЕ КОПИРОВАНИЕ
----------------------------------------------------------------
Регулярно копируйте папки:
  backend/data/      (база JSON)
  backend/uploads/   (прикреплённые документы)
Пример команды PowerShell:
  Copy-Item -Recurse backend\data, backend\uploads -Destination "backups\v2.1.0_$(Get-Date -Format 'yyyy-MM-dd')"
